# Dispute2Suit REST API v1 Documentation

**Version:** 1.0  
**Base URL:** `https://your-domain.manus.space/api/v1`  
**Last Updated:** March 29, 2026

---

## Overview

The Dispute2Suit REST API v1 provides programmatic, read-only access to client, case, document, and dashboard data for authorized partners. Every request is scoped to the partner associated with the API key, ensuring strict data isolation between organizations. The API is designed for integration with external dashboards, reporting tools, and partner-facing portals.

All endpoints return JSON and follow a consistent response envelope. Authentication is handled via bearer tokens (API keys) issued through the admin panel.

---

## Authentication

Every request to the API must include a valid API key in the `Authorization` header using the Bearer scheme. API keys are generated by an administrator through the **API Keys** page in the admin dashboard and are tied to a specific partner organization.

```
Authorization: Bearer d2s_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
```

API keys follow the format `d2s_` followed by 40 random alphanumeric characters (44 characters total). The first 12 characters serve as a lookup prefix; the full key is verified against a bcrypt hash stored in the database. Keys are shown in plaintext exactly once at creation time and cannot be retrieved afterward.

### Key Lifecycle

API keys support the following states, managed through the admin panel:

| State | Description |
|-------|-------------|
| **Active** | The key is valid and accepts requests. |
| **Revoked** | The key has been deactivated by an administrator. Returns `403 Forbidden`. |
| **Expired** | The key has passed its optional expiration date. Returns `403 Forbidden`. |
| **Deleted** | The key has been permanently removed from the system. Returns `401 Unauthorized`. |

### Permission Scopes

Each API key may carry an optional set of permission scopes. When no permissions are set (or the wildcard `*` is present), the key has full access to all endpoints. When scopes are explicitly defined, only matching endpoints are accessible.

| Scope | Grants Access To |
|-------|-----------------|
| `*` | All endpoints (wildcard) |
| `dashboard:read` | `GET /dashboard/stats` |
| `clients:read` | `GET /clients`, `GET /clients/:id` |
| `cases:read` | `GET /cases`, `GET /cases/:id`, `GET /cases/:id/timeline`, `GET /cases/:id/comments` |
| `documents:read` | `GET /cases/:id/documents` |

A request to an endpoint that requires a scope the key does not possess will receive a `403 Forbidden` response with a message indicating the required scope.

---

## Rate Limiting

The API enforces rate limiting on a per-key basis. Each API key prefix is allowed **100 requests per 15-minute window**. When the limit is exceeded, the API returns `429 Too Many Requests` until the window resets.

| Parameter | Value |
|-----------|-------|
| Window duration | 15 minutes |
| Maximum requests per window | 100 |
| Limit scope | Per API key prefix |
| Reset behavior | Counter resets when a new window begins |

## Response Format

All responses use a consistent JSON envelope. Successful responses include `"success": true` and a `data` field. List endpoints additionally include a `pagination` object. Error responses include `"success": false` and an `error` string.

### Successful Response (Single Object)

```json
{
  "success": true,
  "data": { ... }
}
```

### Successful Response (Paginated List)

```json
{
  "success": true,
  "data": [ ... ],
  "pagination": {
    "page": 1,
    "limit": 20,
    "total": 47,
    "totalPages": 3,
    "hasMore": true
  }
}
```

### Error Response

```json
{
  "success": false,
  "error": "Human-readable error message."
}
```

---

## Pagination

All list endpoints support pagination through query parameters. The default page size is 20 and the maximum is 100. Page numbering starts at 1.

| Parameter | Type | Default | Range | Description |
|-----------|------|---------|-------|-------------|
| `page` | integer | 1 | 1+ | The page number to retrieve |
| `limit` | integer | 20 | 1–100 | The number of records per page |

The `pagination` object in the response provides the current page, limit, total record count, total page count, and a boolean `hasMore` flag indicating whether additional pages exist.

---

## Data Sanitization

The API automatically strips sensitive and internal fields from all responses to protect client privacy and system internals.

| Field Stripped | Affected Endpoints | Reason |
|----------------|-------------------|--------|
| `ssn` | All client responses | Personally identifiable information |
| `customFields` | All client and case responses | Internal metadata |
| `fileKey` | Document responses | Internal S3 storage key |
| `uploadedBy` | Document responses | Internal user reference |
| `createdBy` | Task responses | Internal user reference |
| `ipAddress` | Timeline responses | Privacy-sensitive audit data |
| `userAgent` | Timeline responses | Privacy-sensitive audit data |
| `userId` | Timeline and comment responses | Internal user reference |

---

## Error Codes

The API uses standard HTTP status codes. The table below summarizes the codes returned across all endpoints.

| Status Code | Meaning | Common Causes |
|-------------|---------|---------------|
| `200` | OK | Request succeeded |
| `400` | Bad Request | Invalid path parameter (e.g., non-numeric ID) |
| `401` | Unauthorized | Missing header, invalid format, non-existent or unrecognized key |
| `403` | Forbidden | Revoked key, expired key, missing permission scope, partner not found |
| `404` | Not Found | Resource does not exist or belongs to a different partner |
| `429` | Too Many Requests | Rate limit exceeded for this key |
| `500` | Internal Server Error | Unexpected server-side failure |

## Endpoints

### Dashboard

#### GET /dashboard/stats

Returns aggregate statistics for the authenticated partner's clients and cases. This endpoint provides a high-level overview suitable for dashboard widgets and summary reports.

**Permission:** `dashboard:read`

**Request:**

```bash
curl -X GET "https://your-domain.manus.space/api/v1/dashboard/stats" \
  -H "Authorization: Bearer d2s_your_api_key_here"
```

**Response:**

```json
{
  "success": true,
  "data": {
    "totalClients": 12,
    "clientsByStage": {
      "lead": 3,
      "prospect": 2,
      "active": 5,
      "completed": 1,
      "inactive": 1
    },
    "totalCases": 28,
    "activeCases": 18,
    "completedCases": 7,
    "rejectedCases": 3,
    "casesByStatus": {
      "new": 5,
      "pending_review": 4,
      "in_review": 3,
      "more_info_needed": 2,
      "ready_for_attorney": 2,
      "sent_to_attorney": 1,
      "accepted_by_attorney": 1,
      "rejected": 3,
      "settled": 4,
      "settlement_paid_out": 2,
      "closed": 1
    },
    "casesByPriority": {
      "low": 5,
      "medium": 12,
      "high": 8,
      "urgent": 3
    },
    "successRate": 25
  }
}
```

The `successRate` is an integer percentage calculated as `completedCases / totalCases * 100`, rounded to the nearest whole number. The `activeCases` count includes cases with any of the following statuses: `new`, `pending_review`, `in_review`, `more_info_needed`, `ready_for_attorney`, `sent_to_attorney`, and `accepted_by_attorney`. The `completedCases` count includes `settled`, `settlement_paid_out`, and `closed`.

### Clients

#### GET /clients

Returns a paginated list of clients belonging to the authenticated partner. Supports filtering by stage and searching by name or email. Client records are sanitized to exclude SSN and custom fields.

**Permission:** `clients:read`

**Query Parameters:**

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `page` | integer | No | Page number (default: 1) |
| `limit` | integer | No | Records per page (default: 20, max: 100) |
| `stage` | string | No | Filter by client stage |
| `search` | string | No | Case-insensitive search across name and email |

**Valid `stage` values:** `lead`, `prospect`, `active`, `completed`, `inactive`

**Request:**

```bash
curl -X GET "https://your-domain.manus.space/api/v1/clients?stage=active&search=smith&page=1&limit=10" \
  -H "Authorization: Bearer d2s_your_api_key_here"
```

**Response:**

```json
{
  "success": true,
  "data": [
    {
      "id": 1,
      "partnerId": 1,
      "firstName": "John",
      "lastName": "Smith",
      "email": "john.smith@example.com",
      "phone": "555-0100",
      "stage": "active",
      "createdAt": "2026-03-15T10:30:00.000Z",
      "updatedAt": "2026-03-28T14:00:00.000Z"

  ],
  "pagination": {
    "page": 1,

    "total": 1,
```

### Cases

#### GET /cases

**Permission:** `cases:read`

**Query Parameters:**

| Parameter | Type | Required | Description |

| `status` | string | No | Filter by case status |
| `priority` | string | No | Filter by case priority |

## Enum Reference

### Client Stage

| Value | Description |
|-------|-------------|
| `lead` | Initial contact, not yet qualified |
| `prospect` | Qualified lead under evaluation |
| `active` | Engaged client with active services |
| `completed` | All services successfully delivered |
| `inactive` | Client is no longer active |

### Case Status

| Value | Description |
|-------|-------------|
| `new` | Case recently created, awaiting initial review |
| `pending_review` | Submitted for internal review |
| `in_review` | Currently under active review |
| `more_info_needed` | Additional information requested from client |
| `ready_for_attorney` | Review complete, ready for legal assignment |
| `sent_to_attorney` | Forwarded to assigned attorney |
| `accepted_by_attorney` | Attorney has accepted the case |
| `rejected` | Case has been rejected |
| `settled` | Case reached a settlement |
| `settlement_paid_out` | Settlement funds have been disbursed |
| `closed` | Case is fully closed |

### Case Priority

| Value | Description |
|-------|-------------|
| `low` | Non-urgent, standard processing |
| `medium` | Normal priority (default) |
| `high` | Elevated priority requiring prompt attention |
| `urgent` | Critical priority requiring immediate action |

## Quick Start Example

The following example demonstrates a typical integration workflow: authenticating, fetching dashboard statistics, listing clients, and retrieving case details.

```bash
# 1. Set your API key
API_KEY="d2s_your_api_key_here"
BASE="https://your-domain.manus.space/api/v1"

# 2. Fetch dashboard overview
curl -s -H "Authorization: Bearer $API_KEY" "$BASE/dashboard/stats" | jq .

# 3. List active clients
curl -s -H "Authorization: Bearer $API_KEY" "$BASE/clients?stage=active&limit=5" | jq .

# 4. Get details for a specific client (ID 1) including their cases
curl -s -H "Authorization: Bearer $API_KEY" "$BASE/clients/1" | jq .

# 5. List all high-priority cases
curl -s -H "Authorization: Bearer $API_KEY" "$BASE/cases?priority=high" | jq .

# 6. Get full case details with tasks and documents
curl -s -H "Authorization: Bearer $API_KEY" "$BASE/cases/3" | jq .

# 7. View the case timeline
curl -s -H "Authorization: Bearer $API_KEY" "$BASE/cases/3/timeline" | jq .
```

## Notes

**Data Scoping.** All data returned by the API is automatically scoped to the partner organization associated with the API key. A partner cannot access clients, cases, or documents belonging to another partner, even if the resource IDs are known. Requests for resources outside the partner's scope return `404 Not Found` rather than `403 Forbidden`, preventing information leakage about the existence of resources.

**Read-Only Access.** The current API version (v1) provides read-only access. There are no endpoints for creating, updating, or deleting resources. All write operations must be performed through the Dispute2Suit web application.

**Timestamps.** All timestamps in API responses are in ISO 8601 format with UTC timezone (e.g., `2026-03-28T14:00:00.000Z`). Clients should parse these as UTC and convert to local time for display purposes.

**API Key Management.** API keys are created, revoked, reactivated, and deleted exclusively through the admin panel at `/admin/api-keys`. There is no self-service API key provisioning endpoint. Store your API key securely upon creation, as it cannot be retrieved after the initial display.
